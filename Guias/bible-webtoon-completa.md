# BIBLE DE PRODUCCIÓN WEBTOON — NPAD

Basada en WEBTOON Canvas Resource Handbook (Creator 101), Clip Studio Tips, Comistitch, Lemoon Studio, Multic y análisis profesional 2026.

Documentación maestra para generar **la historieta escrita + gráfica** capítulo por capítulo.

---

## 1. FORMATO TÉCNICO (OBLIGATORIO)

| Parámetro | Valor | Notas |
|---|---|---|
| **Ancho** | 800 px | Fijo. Nunca variar. |
| **Alto por pantalla** | 1280 px | Máximo por imagen. Unidad = 1 pantalla (1-2 viñetas). |
| **Resolución de trabajo** | 1600 × 2560 (2×) | Exportar a 800×1280. |
| **Formato** | JPG/JPEG | PNG solo cuando haya transparencia obligatoria. |
| **Peso por imagen** | ≤ 2 MB | Ideal 0,8–1,5 MB. |
| **Peso por episodio** | ≤ 20 MB | Hasta 100 imágenes. |
| **Viñetas por pantalla** | **1 o 2**. Máx. 2 | 3 viñetas prohibidas. Regla no negociable. |
| **Separación entre viñetas (gutter)** | Mín. 200 px | Ver §4. |
| **Dirección de lectura** | Arriba → Abajo | Flujo vertical webtoon. |

> **Regla de oro:** Un capítulo = **pila de pantallas 800×1280** (1-2 viñetas cada una). Nunca capítulo en una sola imagen.

## 2. UNIDADES Y LONGITUD POR CAPÍTULO

| Unidad | Definición |
|---|---|
| **Viñeta/Panel** | Momento narrativo (lo escrito). |
| **Pantalla/Screen** | Imagen 800×1280 (1-2 viñetas). |
| **Episodio/Capítulo** | Bloque entregable semanal. |

| Género (este proyecto) | Pantallas | Viñetas | Scroll (px) |
|---|---|---|---|
| **Acción/Terror urbano** | **60–74** | **60–128** | **76.800 – 94.720** |
| **Espec del proyecto** | **74** | **128** | **94.720** |

**Cap01 = canon (74 pantallas, 128 viñetas, 94.720 px). Todos los caps 7-200 deben mantener 60-74 pantallas.**

## 3. ESTRUCTURA DE CAPÍTULO (3 ACTOS)

Obligatorio en todos los capítulos:

| Acto | Pantallas aprox. | Función |
|---|---|---|
| **1. Gancho** | Pantallas 1–10 (10–15%) | Algo que pide explicación. **Debe enganchar antes de pantalla 5.** |
| **2. Desarrollo** | Pantallas 11–55 (70–80%) | Avanza trama/pelea. Aquí va el segundo gancho. |
| **3. Cierre** | Últimas 10–15 pantallas (15–20%) | Cliffhanger o beat emocional. |

**Segundo gancho OBLIGATORIO** en **30–40%** del capítulo. Debe escribirse explícitamente: `> SEGUNDO GANCHO (pantalla X, YY%) — descripción`.

**Cierres:** 2 de cada 3 emocionales, 1 de cada 3 de trama. Nunca 3 de trama seguidos.

---

## 4. RITMO Y GUTTERS (El gutter = tiempo)

| Valor (px) | Sensación | Cuándo usar |
|---|---|---|
| **50–100** | Rapidísimo | Puñetazos, persecución, staccato |
| **100–150** | Rápido | Acción, ráfagas |
| **200–300** | Latido | Reacción, frase que cae |
| **300–500** | Lento | Beat emocional, pausa |
| **400–600** | Cambio de escena | Exterior–interior, día–noche |
| **600–800** | Antes de revelación | Silencio previo a gancho/cliffhanger |
| **1000–1020** | Silencio total | **Viñeta de silencio T5** (pantalla blanca enorme). Úsese con moderación (1-2 por capítulo). |

**Regla:** gutters SIEMPRE varían. Nunca iguales. Acción = gutters cortos. Emoción = gutters largos.

## 5. COMPOSICIÓN, PLANOS Y FLUJO

### Planos (obligatorio declarar por viñeta)

| Plano | Uso narrativo |
|---|---|
| `general` | Contexto, ciudad, espacio |
| `entero` | Cuerpo completo |
| `americano` | Rodillas hacia arriba |
| `medio` | Cintura hacia arriba (diálogo) |
| `primer plano` | Emoción |
| `primerísimo` | Impacto emocional |
| `detalle` | Mano, ojo, objeto, arma |
| `espaldas` | Mirada hacia lejos, soledad |
| `contrapicado` | Desde abajo (épico, amenazante) |
| `picado` | Desde arriba (vulnerable, pequeño) |
| `silueta` | Tensión, misterio |
| `grupo` | Varios personajes |
| `partida` | Dos escenas |
| `a sangre` | Sin marco (máxima intensidad) |
| `silencio` | Viñeta vacía/pause |

**Una sola acción por viñeta.** Si hay dos acciones → dividir en dos viñetas.

**Transiciones obligatorias:** `CORTE A:` o `FUNDIDO A:` en cada cambio de escena.

**Flujo de lectura:** arriba → abajo. Guiar el ojo con composición (líneas de dirección).

## 6. GLOBOS, LETRA Y SFX

| Tipo | Borde | Uso |
|---|---|---|
| **Habla** | Redondeado, limpio | Normal |
| **Pensamiento** | Nube | Solo casos justificados |
| **Grito** | Estrella/afilado, irregular | Grita (1–4 palabras). Nunca frase larga. |
| **Documento/Narrador (Sistema)** | Rectangular | **Cajas de narración** (letra de formulario, seca) |
| **Teléfono/Radio** | Rectángulo con ondas | Cuando corresponda |
| **SFX** | Sin globo o estrella irregular | **Efecto de sonido dibujado** (integrado con el arte). |

**Reglas:** Máx. **3 globos por viñeta**. Globo cerca de boca, nunca tapa golpe/cara. Cajas arriba o abajo, nunca en medio. **Letra legible 16–24 px** (trabajo a 2×). Orden de lectura arriba→abajo.

### SFX (Onomatopeyas) — OBLIGATORIO dibujadas

- **En ESPAÑOL únicamente.** Cero inglés, cero kana.
- Integradas con el arte (solapan dibujo). Peso/tamaño = volumen. Contorno negro para legibilidad. Dirección/inclinación = velocidad. Baseline irregular = vibración.
- Al final de cada capítulo: bloque obligatorio

```text
SONIDOS DEL CAPÍTULO:
PUM (recto), CRAAACK (rasgado), ZAS (curvo), GRRAAAH (a sangre), TUM (grave), FSSHHH (suave), KRAAK (quebrado), CRASH (rotura). Ningún carácter japonés.
```

**Nunca** usar "Sound effect:" en inglés. Usar **`SFX:`** en prompts Stitch.

## 8. COLOR, ILUMINACIÓN Y ARTE

- **Color plano + cel-shaded (2 tonos)**. Sin degradados suaves, sin ruido excesivo.
- **Dirección de luz consistente por escena.** Misma dirección en toda la pantalla/escena.
- **Paleta narrativa:** fríos = tensión/misterio, cálidos = emoción/calidez. Amarillo chillón solo para Ren (marca).
- **Fondos:** funcionales, no compiten con personajes. Usar fondos simples cuando hay acción, detallados en establecimiento.
- **Sin desenfoque (blur).** Profundidad por aplanado/contraste.
- **Sin chrome de lector** (HUD, barras, menús, LEVEL UP, manos sosteniendo móvil, URL). Prohibido.

## 9. STORYBOARD PROFESIONAL → PROMPTS IA

### A. Estructura de guion por capítulo (`capNN.md`)

Debe seguir exactamente el formato de `cap01.md`:

1. **Ficha** (título, géneros, estructura, fondos, personajes con nombre, contadores: pantallas, viñetas, globos, cajas, SFX)
2. **Mapa de pantallas Bloque A** (tabla: S, Tipo T1–T6, Viñetas, Alturas, Gaps)
3. **Las viñetas Bloque A** (V01–VXX con: Plano, Composición, Acción, SFX, Globo, Caja de narración)
4. **Mapa de pantallas Bloque B** (igual)
5. **Las viñetas Bloque B**
6. **Tablas de texto**: Globos de diálogo, Globos 1 palabra, Cajas de narración, SFX, Sonidos descritos (no dibujados)
7. **Semillas para siguientes capítulos**
8. **Qué NO hace**

**Contadores DEBEN coincidir** (ficha = filas de tablas). Sin discrepancias.

### B. Prompt para Google AI Studios (`prompts/capNN-google.md`)

Incluir:

- **Rol del sistema:** "Eres un storyboard artist y director de webtoon profesional especializado en formato vertical 800×1280 (scroll infinito)."
- **Biblia completa** (canon C1–C12, anclas literales, retícula T1–T6, reglas SFX español, cero inglés/kana/HUD)
- **Referencia visual:** mencionar `cap01.md` como referencia de calidad (estructura, ritmo, tono). **No copiar imágenes, solo estructura.**
- **Instrucciones globales:** mantener consistencia personajes 100%, 1-2 viñetas/pantalla, suma 1280 exacta, gutters variables, segundo gancho marcado, transiciones CORTE A:/FUNDIDO A:.
- **Por pantalla:** todos los campos completos (plano, composición, personajes, acción 1 línea, efectos, SFX, globo, gutter arriba/abajo, fondo).

### C. Prompt para Stitch (`prompts/capNN-stitch.md`)

**Plantilla OBLIGATORIA por pantalla (copiar tal cual):**

```text
CAP NN, pantalla X de YY. Viñeta VZZ.
Ancla NPAD aplicada.
PLANO: <declarado>
COMPOSICION: <tercios, qué lado, fondo>
PERSONAJES: <descripción corta y fija, literal>
ACCION: <una sola acción>
EFECTOS: <líneas, forma, color, dirección>
SFX: <palabra en español> <contorno> <tamaño, encima de qué>
GLOBO: <personaje, texto literal, posición y cola>
GUTTER ARRIBA: <px>   GUTTER ABAJO: <px>
```

**Bloque final obligatorio (una única vez por capítulo):**

```text

<lista de SFX usados en español, sin inglés/kana>. Ningún carácter japonés.
```

## 11. CORRECCIONES APLICAR A COMPOSITOR.PY

Arreglos obligatorios (ya detectados):

1. **Mover `caja_narracion()` ANTES del `return`** cuando `paneles == []` (pantallas T5/T6 con narración). Evita perder narraciones (bug s11==s22).
2. **No usar `mv`/`rm` de shell en Windows.** Usar `shutil.move`, `shutil.rmtree` (o `os.replace`). `mv`/`rm` no existen en cmd/PowerShell por defecto.
3. **Detectar extensión real del destino.** Si la capa de narración es PNG, no sobreescribir con nombre `.jpg` forzando firma errónea. Mejor generar siempre **JPG** limpio (`-quality 88–95`, `-alpha remove`).
4. **Validar geometría** con tolerancia 0 (estricto). Si falla, lanzar error con `n, total, esperado`.
5. **Soportar `magick` en PATH o detectar ImageMagick.** Añadir fallback con mensaje claro.

> **Nota:** El cap01 actual tiene placeholders (PNG 1-bit). Los nuevos capítulos deben generar **arte real** siguiendo esta bible.

## 13. INSTRUCCIÓN MAESTRA PARA LA IA

Al generar **todos los capítulos 7–200**:

1. **Leer SIEMPRE** `arco-200.md` + `bible-webtoon-completa.md` antes de generar cada `capNN.md`.
2. **Usar cap01.md como referencia de estructura, NUNCA como copia de trama.** Inventar siguiendo T5–T8.
3. **Respetar canon C1–C12 al 100%.**
4. **Generar los 3 archivos por capítulo:** `capNN.md`, `prompts/capNN-google.md`, `prompts/capNN-stitch.md`.
5. **Mantener calidad narrativa profesional (novela gráfica):** subtexto, coste > espectáculo, motivo recurrente, ritmo controlado.
6. **Historieta ESCRITA + GRÁFICA.** Los prompts deben estar listos para generar imágenes directamente (sin editar).
7. **Trabajar capítulo por capítulo, completo y validado con checklist antes de pasar al siguiente.**

**Objetivo:** Crear una historia sólida, profesional y legible en webtoon, con coherencia total del canon y prompts production-ready para Google AI Studios + Stitch.
